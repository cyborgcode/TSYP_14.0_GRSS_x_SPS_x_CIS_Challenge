# Evaluation & Performance Report

**Track 1:** Secure Ground-Link Testbed
**Phase 1 Submission – Anonymous Evaluation**

---

## 1. Executive Summary

This report gives the measured detection accuracy, false-alarm rate and processing overhead of the
testbed pipeline (`testbed/`). Telemetry comes from TerraSAR-X, a sun-synchronous LEO satellite at
514 km, downlinking at X-band (8477.8 MHz) to the Zaghouan ground station in Tunisia, with the four
red-team vectors of the live dashboard injected in bursts.

Every attack packet was denied, in every run, from the first packet of each burst. Only 0.7–1.4%
of genuine packets were held back, all of them by the Isolation Forest. The two security layers
are complementary: stealth spoofing fools the RF checks about half the time and data tampering
always does, and both are caught by cryptography; noise jamming carries authentic frames and is
caught only by the RF checks.

**Scope.** All traffic is synthetic, generated by `testbed/ingester.py`. These figures describe
the testbed, not a real link, and must be re-measured on the official reference datasets before
they are reported as results.

## 2. Quantitative Performance & Metrics

Six seeded runs (seeds 1, 2, 3, 4, 5 and 14). Each run trains the detector on 3,000 nominal
packets (5 passes), then scores 6,000 held-out nominal packets interleaved with 200 attack bursts
(50 per vector, 30 packets each).

| Evaluation Metric | Target | Measured (6 seeds) | Status |
| :--- | :--- | :--- | :--- |
| **False-alarm rate** (genuine packets denied) | $< 2.0\%$ | $0.73$–$1.43\%$, median $0.94\%$ | ✅ Met |
| **Per-packet processing time** (detector + trust anchor + policy) | $< 100\text{ ms}$ | $5.8\text{ ms}$ mean, $\le 7.9\text{ ms}$ p95 | ✅ Met |
| **Ledger overhead** (authenticate + SHA-256 chain one block) | $< 10\text{ ms}$ | $0.06\text{ ms}$ mean | ✅ Met |
| **Attack packets denied** | $100\%$ | $100\%$ of 6,000 per run, all four vectors | ✅ Met |
| **Time to first denial** | first packet | packet 1 of every burst | ✅ Met |
| **Ledger tamper test** (one verdict edited mid-chain) | detected | detected in every run | ✅ Met |

Processing times were measured on one core of an Intel Xeon @ 2.10 GHz (Python 3.11,
scikit-learn 1.9.1). The detector's Isolation Forest scoring accounts for almost all of it.

## 3. Adversarial Test Results

Share of packets flagged by each layer (range over the six seeds):

| Traffic | Physics gate | Isolation Forest | Trust anchor | Zero trust: denied |
| :--- | ---: | ---: | ---: | ---: |
| Genuine | 0% | 0.7–1.4% | 0% | 0.7–1.4% |
| Frequency Hijacking | 100% | 100% | 100% | **100%** |
| Stealth Spoofing | 16–18% | 36–52% | 100% | **100%** |
| Noise Jamming | 100% | 98–99% | 0% | **100%** |
| Data Tampering | 0% | 0.5–1.1% | 100% | **100%** |

1. **Frequency Hijacking (+14.2 MHz offset).**
   - *Behaviour:* the carrier jumps to ~8492 MHz, which no orbit can produce. The physics gate
     and the Isolation Forest both flag it. The rogue frames are also sealed with a key the
     attacker does not share, so every one fails its HMAC check.
   - *Outcome:* denied by all layers; every rejection is recorded in the hash-chained ledger.
2. **Stealth Spoofing (node 0x99A2, forged MAC headers and nonces).**
   - *Behaviour:* the spoofer stays on the Doppler track and only 3.2 dB below the link budget,
     so the RF checks catch it only part of the time. Its frames fail the HMAC check, it reuses
     recent nonces, and its hardware token does not match the satellite's registration.
   - *Outcome:* denied by the trust anchor and the zero-trust policy on every packet. This is
     the case that needs cryptography: RF anomaly detection alone would miss about half of it.
3. **Broadband Noise Jamming (RSSI to −96.5 dBm).**
   - *Behaviour:* RSSI collapses far below the link budget. The frames that get through are
     genuine, so the trust anchor accepts them; the physics gate flags every one.
   - *Outcome:* denied on RF evidence alone, without stopping the ingestion pipeline. On the
     dashboard, this is where fallback routing to GS-MAT takes over.
4. **Data Tampering (one payload bit flipped in transit).**
   - *Behaviour:* the genuine satellite sends and seals the frame; a relay in the path flips one
     payload bit afterwards. The RF is untouched, so the Isolation Forest flags it no more often
     than genuine traffic (its normal false-alarm rate), and the physics gate never does.
   - *Outcome:* the recomputed HMAC-SHA256 no longer matches the seal, so the trust anchor
     rejects every altered frame and zero trust drops it. Keys are not rotated: the relay never
     had the key. This is the case that needs hash verification and nothing else.

The same scenarios run live in the web dashboard (React, `dashboard/`), where each attack also
drives the 3D beam, the Carrier Frequency and RSSI charts and the `trust_anchor.py` log. The
dashboard runs browser ports of `trust_anchor.py` (same frame format, HMAC seal, replay window and
SHA-256 chain from the same genesis block; golden vectors are checked by both test suites) and
`detector.py` (same features, physics limits and 1 % contamination). Its packet inspection drawer
shows, for every frame, the raw payload, the MAC received against the MAC recomputed, the nonce
check, the ledger block, the detector features, the Isolation Forest score and confidence, and the
zero-trust decision.

## 4. Conclusion & Reproducibility

The results support the design: cheap cryptographic sealing plus unsupervised RF anomaly detection
protect the ground link without changes to the satellite hardware, and neither layer suffices
alone. Stealth spoofing and data tampering need the cryptography, and jamming needs the RF checks.

Reproduce one run (prints the red-team audit, then the measured table):

```bash
pip install -e ".[dev]"
python -m testbed.validator --seed 14
```

Every figure above comes from `testbed.validator.measure()` with the seeds listed; the tests in
`tests/test_testbed.py` check the same properties on a smaller run.
